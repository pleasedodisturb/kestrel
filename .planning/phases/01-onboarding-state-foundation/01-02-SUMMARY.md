## What Was Built

**Alembic migration** (`alembic/versions/e68f373345cd_add_onboarding_states_table.py`): Autogenerated migration creating `onboarding_states` with all 7 `_at` timestamp columns, 7 `_via` string columns, `profile_id` FK (unique index), `current_step`, `created_at`, `updated_at`. `alembic upgrade head` applies cleanly.

**Service layer** (`src/career_os/services/onboarding.py`):
- `STEP_ORDER`: Module-level list of 7 steps (equals `VALID_STEPS` from schemas — verified in tests)
- `get_onboarding_status(profile_id, db)`: Returns synthesized empty response if no DB row (assumption A2), populated response otherwise
- `mark_step_complete(step, via, profile_id, db)`: Creates row on first call (D-13), idempotency guard on `_at` field (D-06), `OnboardingValidationError` for unknown steps (T-1-01 mitigation), `_utcnow()` sets server-side timestamp (D-05)
- `_compute_next_step`, `_compute_progress_pct`: Pure functions using `getattr` for dynamic column access

**Tests** (`tests/test_onboarding_service.py`): 11 tests covering all `<behavior>` scenarios — all passing. Also implemented `test_state_persisted` and `test_error_fields` stubs from `test_onboarding_api.py` (Plan 00 Wave).
