## Git delivery (binding, identical in every Phase 11 plan)

1. **Branch.** Every Kestrel deliverable lands on `G-2039/map`, cut from `origin/main` (main tip when planned: `21ac4b0d`). Never base work on `G-2013/v2-lean-milestone`: most of its commits carry no `Reviewed-by` trailer, and the `Review trailers` CI job checks every commit in the PR range.
2. **Pre-execution step (orchestrator or maintainer, once, before `/gsd-execute-phase 11`).** In the main checkout, after these plans are committed on the milestone branch: `git fetch origin main`; `git switch -c G-2039/map origin/main`; `git restore --source=G-2013/v2-lean-milestone -- .planning/`; one commit `docs(G-2039): carry the v2.0 planning docs onto the Map branch` whose body says why one reviewed commit replaces the unsigned milestone history; `review-push run`, answer findings, `review-push sign`, `git push -u origin G-2039/map`. Execute-phase then runs from this checkout, so executor worktrees (`worktree.baseRef: head`) fork from `G-2039/map` and land back on it. This is the default for open question OQ-3.
3. **Commits.** Conventional, scoped to the ticket, each with a body saying what changed and why: `test(G-2039): ...` for goldens, mapping tables, ledger tests, MAP-05 and the marker; `docs(G-2039): ...` for ledger data, counts and the verdict list. End each message with the attribution lines the session supplies.
4. **Staging.** Stage by explicit path only. The checkout carries untracked folders (`.planning/research/.cache/`, `.gsd/`, older quick-task folders) that main's `.gitignore` does not cover; they must never be committed.
5. **Push.** Before every push of `G-2039/map`: `review-push run`, answer every medium+ finding (`review-push disposition {id} rejected --reason ...`, or fix and run again), `review-push sign`, `git push`. Never amend after signing without a fresh run; rebase, never merge main in. When this plan ran in an isolated executor worktree, the orchestrator does this after landing the plan's commits on `G-2039/map` by rebase or cherry-pick.
6. **PR.** One PR for the phase, opened by plan 11-06 after plan 11-05 has crossed the verdict list. The maintainer merges, only on green CI.

**This plan commits nothing to Kestrel except its SUMMARY.** Its commits go to the private pipeline's repository, following that repository's own commit and review rules (its own CLAUDE.md or AGENTS.md). Do not send the retrospective to any external reviewer unless that repository's rules require it; the retrospective is personal data.

**Shell variables used by every `<automated>` command:** `MAP_PRIVATE_REPO` (the private pipeline's repository root) and `MAP_EXPORT` (the export folder created in Task 1), both set by the executor from `private/retrospective/README.md` at run time and never written to any Kestrel file; `KESTREL` is the Kestrel checkout root (cwd).

## Export contract (restated from tests/ports/boundary.py, which plan 11-03 builds in parallel)

- **11-VERDICTS.md**: a line starting `Vocabulary:` containing `keep / scope-and-plan / park / remove` and stating that D-02's `kept / trimmed / parked / cut` map to them in that order; a line starting `Source:` naming "the private pipeline's repository", the 40-hex commit of the session doc and the window `2026-06 to 2026-10`; one pipe table with columns `id | kind | name | ref | verdict | profile_scope | non_technical | count | reason`. Flows are `F-01`, `F-02` ... and features `X-01` ... (all F rows first, numeric order); `ref` is `-` or a tag such as `cut-a:ticktick`; `count` is the integer number of observed runs or uses in the window; `reason` is at most 300 characters, no pipe characters.
- **REQUIRED_REFS** (each needs a row): `cut-a:ticktick`, `cut-a:icalendar`, `cut-a:worker`, `cut-a:dashboard`, `cut-a:bmad`, `cut-a:workflows`, `cut-a:release-channels`, `cut-a:railway`, `cut-a:web-app`, `retire:tools`, `retire:daily-scan-workflow`, `retire:automation-glue`, `retire:pushover`. The Railway and web-app rows record the maintainer's 2026-11 decisions as their reason (CUT-09, CUT-10), so every Cut A item can cite a verdict.
- **11-ARRIVAL-COUNTS.csv**: header `source,month,arrived,survived_prefilter,scored,shortlisted,applied`; months `2026-06` to `2026-10`; non-negative integers; sources only from FLOOR_SOURCES (`aijobs, arbeitnow, ashby, germantechjobs, greenhouse, himalayas, jobicy, lever, personio, remoteok, remotely.de, remotive, smartrecruiters, startupjobs, weworkremotely, workable`), JOBSPY_BOARDS (`indeed, linkedin, glassdoor, google, zip_recruiter`), `arbeitsagentur`, `manual`, `other`; per-company ATS sources rolled up to their family; rows sorted by (source, month); an absent row means not recorded, 0 means a recorded zero.
- **PORT_LEDGER_PRIVATE.yaml**: `schema: 1`; rows sorted by id `P-01` ...; keys `id, private: true, description, run_status (scheduled|by_hand|dead), inputs, outputs, disposition (port|keep_until_retire|delete), reason` (reason required for dead and delete); no `path` key, no path-like token, no script filename.
- **Every exported cell**: generic names only; no company, person or recruiter name; no date finer than a month; no quotation marks; no URL; no money amount; no path, repository name or script name; no mood or narrative. Reasons state product evidence: frequency band, what the flow produced, where it stalled, profile dependence.
