- **Family B (registered here, filled by plans 11-04 and 11-05):** one scrubbed, output-only sample per output class of the private pipeline's real recorded runs (`private_scan_arrivals`, `private_dedup_verdicts`, `private_eligibility_verdicts`, `private_scoring`, `private_digest`; the gate verdicts already cross the same way). ## Family B record contract (implemented by `private_golden_problems`; plans 11-04 and 11-05 build and check against it)

- **Classes** (`FAMILY_B_CLASSES`): `private_scan_arrivals`, `private_dedup_verdicts`, `private_eligibility_verdicts`, `private_scoring`, `private_digest`. Golden file `tests/replay/golden/{class}.jsonl`. No HARNESS entry: excluded from replay and from `--check` recompute; checked by schema, invariants, sha256 and PII only.
- **Scope.** Each file is a subset of the maintainer's real runs, anonymised and scrubbed under D-03, output-only: `input` holds only the posting fields the recorded output carried, never the dossier, profile or config that produced it, and the config does not cross in substance either (see "Config-derived rows"). Profile-specific by construction (D-13): every record and every MANIFEST entry says `profile_scope: "maintainer"`. Any replay of a port against Family B runs only inside the private pipeline's repository with the private dossier.
- **MANIFEST entry:** `golden`, `sha256`, `status` (`awaiting_private_run` or `frozen`), `producers` {"the private pipeline": SHA}, `producer_commit` (the same SHA), `producer_row` (a `P-NN` row id of `tests/ports/PORT_LEDGER_PRIVATE.yaml`), `profile_scope` "maintainer", `inputs` "scrubbed", `replay` (the class's value in `FAMILY_B_REPLAY`, present from the awaiting registration on and never changed by freezing), `generated` (YYYY-MM). While awaiting: `golden`, `sha256`, `producer_commit`, the producer value, `producer_row` and `generated` are null.
- **Envelope (every line):** exactly the keys `id` (`^[a-z0-9-]{3,40}$`, unique, rows sorted by id), `month` (`^\d{4}-\d{2}$`), `scrubbed` (JSON true), `profile_scope` ("maintainer"), `input` (object), `output` (object). Each line equals `dump_jsonl`'s encoding of its record (sorted keys, compact separators, UTF-8, LF). Row count: at least the class minimum (20 rows; `private_digest` at least 3) and at most 200. No two rows carry the same (`input`, `output`) pair.
- **Identity tokens (per class).** Each class has its own identity map, so `Company-NN`, a `company-NN` source suffix, `Person-NN`, `Email-NN`, `Req-NN`, `Home-NN` and the `https://example.invalid/{token}` URL tokens of one class are unrelated to the same token in any other class, and the five files cannot be joined on a token. Token numbers are assigned in the order of a keyed hash of the normalised raw value (a per-class secret kept with the private maps), so no alphabetical or first-seen order lines up across files; both postings of a `private_dedup_verdicts` pair use that class's one map; row ids are per-class sequence numbers, never derived from a job key, URL or private id.
- **Posting object** (the Kestrel `ScrapedJob` / `Tier0Job` field set, so one loader reads both families). Required: `title` (verbatim), `company` (`^Company-\d{2,3}$`), `location` (verbatim, or `^Home-\d{2,3}$` under "Config-derived rows"), `url` (`^https://example\.invalid/[a-z0-9-]+$`), `source` (`^(tier0:)?[a-z][a-z0-9._-]*(:company-\d{2,3})?$`), `remote` (bool, verbatim). Optional (recorded only privately or not on every run): `salary` (verbatim band), `posted` (`^\d{4}-\d{2}$` or ""), `age_days` (integer posting age, computed before dates were coarsened), `offices` (list of location strings, each verbatim or `Home-NN`), `remote_policy` (verbatim), `tags` (list of strings), `search_keyword` (verbatim), `job_id` (`^Req-\d{2,4}$`), `recruiter` and `contact` (`^Person-\d{2,3}$`), `email` (`^Email-\d{2,3}$`), `description` (only ""), and identity-derived decision flags computed from the real identity before scrubbing so the golden keeps the branch (D-03): `dream_tier`, `blocked`, `soft_flag` (bool, false in every exported record, see "Config-derived rows"), `api_submittable` (bool), `ats_family` (`^[a-z][a-z0-9.]*$`).
- **Per class:** `private_scan_arrivals`: input {`source`, optional `search_keyword`}, output one posting object as it arrived. `private_dedup_verdicts`: input {`a`: posting, `b`: posting}, output {`duplicate` (bool); optional `kept` ("a" or "b"), `fuzzy_ratio` (number), `reason_code`}. `private_eligibility_verdicts`: input posting, output {`geo_class` (verbatim string); optional `prefilter_skip` (bool), `score_cap` (integer or null), `blocked`, `soft_flag` (bool, false only), `reason_code`}. `private_scoring`: input posting plus optional `geo_class`, output {`fit_score` (number); optional `tier` ("T1", "T2", "T3" or null), `review_flag` (bool), `floored` (bool, false only), `estimated_salary`, `effort_flag` (verbatim), `prep_level` (integer), `scorer` (`^[a-z0-9._-]{2,40}$`), `reason_code`}. `private_digest`: one line per digest run, structured rows only, never the digest's Markdown: input {`config` {optional `mode` (verbatim), `min_score` (number), `hours_old` (integer)}, `counts` {optional `arrived`, `scored`, `shortlisted` as non-negative integers}}, output {`rows`: a list, possibly empty, in the digest's order, of objects with exactly `company` (`Company-NN`), `title` (verbatim), `location` (verbatim or `Home-NN`), `fit_score` (number), `tier` ("T1", "T2", "T3" or null), `effort_flag` (verbatim string or null) and `source` (the posting `source` shape); `footer`: JSON null (the digest footer names the producing script and never crosses)}. Every `reason_code` matches `^[a-z][a-z0-9_]{2,40}$`. Free text (fit reasoning, prep notes, review reasons, descriptions, notes, the digest Markdown and its footer) never crosses.
- **Config-derived rows.** A row whose decision depended on the private pipeline's own config is config-derived. Home region (the private geo config's home tokens): in every class, a `location` or `offices` element that contains a home token is replaced by that class's `Home-NN` token, and whenever a record carries `geo_class` "home" (eligibility output, scoring input) its posting's `location` must match `^Home-\d{2,3}$`.
