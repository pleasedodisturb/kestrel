<design_decision>
LOCKED SURFACE CHOICE — **sidePanel is the primary surface, with an in-page overlay as the documented fallback.**
Justification: The domain refresh (03-extension-capabilities.md) recommends MV3 `sidePanel` as the persistent companion; it does not obscure the posting, survives scroll/navigation, and needs only the narrow `sidePanel` permission (NOT a host permission). WXT has first-class sidepanel entrypoint support. The floating trigger button (built in 01-03) stays as the in-page affordance.
De-risking: The `ScorePanel` component is written SURFACE-AGNOSTIC (pure props: takes a capture result, emits an onPromote callback) so it mounts unchanged in EITHER the sidePanel OR an in-page shadow-DOM overlay. FALLBACK: if `sidePanel` proves flaky in WXT during execution (e.g. open-on-action wiring, Chrome <140), mount the SAME `ScorePanel` in an in-page shadow-root overlay injected by the 01-03 content script instead — no component rewrite. Record which surface shipped in the SUMMARY.
Chrome sidePanel opens must be tied to a user gesture (`chrome.sidePanel.open` from the action click / the floating button's message) — do not attempt to auto-open on navigation.
</design_decision>

<interfaces>
Capture result shape reaching the panel (from 01-03 messages.ts CaptureResponse):
```typescript
{ ok: boolean; jobId?: string; discoveredJobId?: number;
  fitScore?: number; letterGrade?: string; scoreBreakdown?: unknown[]; gap?: string; error?: string }
```
The 01-03 content script dispatches a DOM CustomEvent `kestrel:capture-result` and/or the popup holds the result; the sidePanel receives the latest result via a small stored "last capture" in chrome.storage.session (set by the background CAPTURE handler) OR a runtime message — pick chrome.storage.session for MV3 worker-restart safety and have the sidePanel read it on mount + subscribe to storage changes.

Add PROMOTE to the message/client contract:
```typescript
// messages.ts
export type ExtMessage = ... | { type: "PROMOTE"; discoveredJobId: number };
export interface PromoteResponse { ok: boolean; applicationId?: number; status?: string; error?: string }
// client.ts
export async function promote(discoveredJobId: number): Promise<PromoteOutcome>  // POST /api/extension/promote {discovered_job_id}
```
Backend /promote (from 01-02): POST /api/extension/promote body `{discovered_job_id}` → `{application_id, status}`; 401 unpaired.

ScoreBreakdownFactor items (from backend score_breakdown JSON) are `{factor/label, score, weight, ...}`-shaped; render defensively (unknown[] — narrow at the boundary).

WXT sidepanel entrypoint: `extension/entrypoints/sidepanel/` (index.html + main.tsx + App.tsx) — React 19 mount, mirrors the existing options/ entrypoint structure. Add `"sidePanel"` to manifest permissions in wxt.config.ts.
Auto-log content script: a SEPARATE `defineContentScript` (`autolog.content.ts`) matching Greenhouse/Lever/Ashby application-form hosts; detect submit by listening for the form submit / the post-submit confirmation URL/DOM for each ATS (small per-ATS heuristic map). On detection, show an injected, dismissible confirmation banner ("Log this application to Kestrel? [Log] [Dismiss]") — user-visible, never silent — then on confirm send PROMOTE (or an advance message) through the worker.
Test env: vitest + jsdom + Testing Library (extension already uses `renderWithProviders`-style setup? check extension/test/setup.ts). ScorePanel tests render with props; autolog detection tests drive jsdom DOM/URL.
</interfaces>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ATS application page → autolog content script | Page is untrusted; the script reads submit signals + injects a confirmation UI, never auto-submits or reads credential fields |
| sidePanel / overlay → background → /promote | Promote crosses the network only via the worker with the paired token |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01D-01 | Repudiation/UX-trust | Silent auto-log (Simplify anti-pattern) | mitigate | Every auto-log requires a VISIBLE, dismissible confirmation before any pipeline write; no silent path exists |
| T-01D-02 | Elevation | Auto-log content script over-broad host access | mitigate | Explicit ATS `matches` allowlist + `activeTab`; NO `<all_urls>` (grep-gated); no host_permissions wildcard |

| T-01D-04 | Tampering | Injected banner XSS from page content | mitigate | Banner rendered in a shadow root with static text; no page-derived innerHTML |
