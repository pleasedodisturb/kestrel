<objective>
Make `/api/extension/capture` real (CONTEXT Part B): accept the extension payload (normalized fields OR raw JD text), create/dedupe a DiscoveredJob, and score it by REUSING `services.scoring.score_job` — never reimplementing scoring or the prompt. Purpose: This is the backend of "the eye" — the payoff. It turns the Phase 0 inert stub into a scored capture, reusing every existing service (scoring, discovery dedupe, application creation).
Output: `services/extension_capture.py`, real `/capture` + `/promote` routes, a refactored reusable `promote_discovered_job_to_application` service, updated schemas + guard test, and full capture test coverage.

DEPENDS ON 01-01: shares `api/extension.py`, `schemas/extension.py`, `tests/test_extension_api.py` — must run after Part A hardening lands (also the CONTEXT-mandated ordering: harden before capture carries real data).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| extension (paired token) → `/capture`, `/promote` | Bearer token now unlocks real scoring (LLM cost) + writes DiscoveredJob/Application rows |
| captured page content → score_job / LLM extraction | Attacker-controlled JD text flows into an AI prompt and the DB |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01B-01 | DoS/cost | `/capture` triggers paid LLM scoring per call (SECURITY T-00-07) | mitigate | Token-gated (require_extension_token, now with TTL from 01-01) + input size cap (extension_max_jd_chars) before any LLM call; single extraction call max |
| T-01B-02 | Tampering/injection | Malicious JD text as prompt input | accept | JD text is data to the scoring model, not code; no eval; size-capped. Existing scoring path already ingests scraped JD text — same trust level |
| T-01B-03 | Spoofing | Cross-profile write via forged profile_id | mitigate | profile_id resolves to the single-user default (1); score_job/DiscoveredJob are profile-scoped; a paired token implies local instance ownership |
| T-01B-04 | Info-disclosure | Capture response leaks internal fields | mitigate | Response is an explicit Pydantic model (fit_score/breakdown/gap only); no raw ORM dump |
| T-01B-05 | DoS | Unbounded capture rate | accept (Phase-1) | Bounded by token + size cap; a per-token capture rate-limit is a fast-follow if abuse appears (noted for reviewer) |
| T-01-SC | Tampering | No new package installs | accept | Reuses existing scoring/discovery/AI deps; no npm/pip install in this plan |
</threat_model>
