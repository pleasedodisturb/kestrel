<!-- Backend wire contract this worker calls. Defined by plan 00-01. Build against it directly. -->

POST {backendUrl}/api/extension/pair    body { pairing_code }   -> { token, instance:{name,version} } | 401
POST {backendUrl}/api/extension/capture bearer header           -> { job_id, status, scored } | 401
GET  {backendUrl}/api/extension/status  bearer header           -> { ok, instance } | 401
GET  {backendUrl}/health                (no auth)               -> 200 {status, database} | fail

Storage keys (chrome.storage.local): `backendUrl` (default "http://localhost:8100"), `extensionToken` (string | null).

Background message API (chrome.runtime.sendMessage -> Promise):
  { type: "PAIR", pairingCode }  -> { ok, token?, instance?, error? }
  { type: "HEALTH" }             -> { ok, state: "connected"|"unpaired"|"backend-down"|"bad-key" }
  { type: "CAPTURE", payload }   -> { ok, jobId?, error? }
  { type: "STATUS" }             -> { ok, instance?, error? }
</interfaces>

    sends the request cookie-less (`credentials: "omit"` — the token travels in an
    `Authorization: Bearer` header, never cookies, matching the backend's credential-less CORS),
    attaches the stored token on capture/status, and wraps fetch in an ~1.5s `AbortController`
    timeout. Map network failure/timeout to a distinct outcome so the worker can report
    `backend-down`.

    entrypoints/background.ts: register `chrome.runtime.onMessage` and route by `type`:
      - PAIR → `client.pair`; on success `storage.setToken(token)`, return {ok,token,instance}.
      - CAPTURE → require a stored token; `client.capture`; return {ok, jobId}.
      - STATUS → `client.status`.
      - HEALTH → compute state: call `/health`; if it fails → `backend-down`; if ok and no
        token → `unpaired`; if ok and token present → call `/api/extension/status`, 200 →

    that must survive — read from `chrome.storage` each time). Use `onMessage` with an async
    handler returning a Promise (WXT/Chrome MV3 promise style). No content scripts, no
    `chrome.scripting`, no capture extraction — that is Phase 1.
