## Research correction (verified by the planner on 2026-09-29)

RESEARCH Finding 5 / Pitfall 3 say pre-commit's ruff hooks bypass the `_alembic` exclude. **That is not what the hooks do.** The cached ruff-pre-commit v0.11.0 manifest (`~/.cache/pre-commit/repo99g5sxjy/.pre-commit-hooks.yaml`) declares `entry: ruff check --force-exclude` and `entry: ruff format --force-exclude`, so the hooks already honour `extend-exclude` for explicitly passed paths. The research's reproduction used a bare `ruff check <file>`, which is not what the hook runs. With ruff 0.15.15, `ruff check src/career_os/_alembic/` reports `Found 164 errors.`, while `ruff check --force-exclude src/career_os/_alembic/` prints `warning: No Python files found under the given path(s)` then `All checks passed!`. Setting `force-exclude = true` in pyproject is still worth doing (DEC-04). It makes bare explicit-path invocations and editor integrations honour the exclude, and it keeps pyproject the single place that states the rule. The pyproject comment written in Task 1 states this accurate rationale, not the research's one.
