The `init` function should accept `--skip` flag (bool, default False) and `--force` flag (bool, default False).

Flow:
1. Non-TTY check (D-03/CLI-03): `if not sys.stdin.isatty(): console.print(Panel("...")); raise typer.Exit(0)`
2. `--skip` check (D-04/CLI-04): create Profile with name="Kestrel User" + mark profile_started + profile_completed, print success, exit
3. DB session + resume detection (D-14): call `get_onboarding_status(profile_id=1, db=db)`. If profile_completed_at is set and not --force, print "Profile already set up. Use --force to redo." and exit
4. Welcome Panel (D-03): `console.print(Panel("[bold]Kestrel[/bold] v{version}\nLet's set up your profile.", border_style="blue"))`
5. Tip (D-08): `console.print("[dim]Tip: Press Enter to skip any question. You can re-run kestrel init later.[/dim]\n")`
6. Get or create Profile: `profile = db.query(Profile).first()` — if None, create `Profile(name="User")`, add to db, flush
7. Mark profile_started: `mark_step_complete(step="profile_started", via="cli", profile_id=profile.id, db=db)`
8. Loop through WIZARD_STEPS with step counter (D-05/CLI-05):
   - Print `"[bold blue]Step {i+1}/{TOTAL_STEPS}[/bold blue]"` before each question
   - `answer = Prompt.ask(label, default="", console=console)`
   - If answer is empty string, skip (keep existing profile value if any)
   - Otherwise store in a dict: `answers[field_name] = answer`
9. Summary table (D-04/PROF-03): build Rich Table with field name + value for each non-None answer. Print it.
10. Confirm (D-04): `if not Confirm.ask("Save this profile?", default=True, console=console): console.print("Cancelled."); raise typer.Exit(0)`
11. Save to Profile: set each field from answers dict on the profile object, `db.commit()`
12. Mark profile_completed: `mark_step_complete(step="profile_completed", via="cli", profile_id=profile.id, db=db)`
13. Success + next step (D-12/CLI-08): `console.print("[green]check[/green] Profile saved!"); console.print("\n[bold]Next:[/bold] Try [bold]kestrel pipeline list[/bold] to see your job matches.")`

Error handling (CLI-07): wrap main logic in try/except OnboardingError, display user_message + resolution. Wrap in try/except Exception for unexpected errors with generic message.

1. **Add first-run callback** (D-09, D-10, D-11) — after the app definition and before subcommand registrations. Add:
```python
@app.callback(invoke_without_command=True)
def main_callback(ctx: typer.Context) -> None:
    """Check onboarding status and show first-run hint if needed."""
    if ctx.invoked_subcommand in ("init", "doctor"):
        return
    if ctx.resilient_parsing:
        return
    if ctx.invoked_subcommand is None:
        # no_args_is_help handles this
        return
    try:
        db = _get_session()
        try:
            from career_os.services.onboarding import get_onboarding_status
            status = get_onboarding_status(profile_id=1, db=db)
            if not status.is_complete:
                console.print(Panel(
                    "[bold]Welcome to Kestrel![/bold]\n"
                    "Run [bold cyan]kestrel init[/bold cyan] to set up your profile.",
                    border_style="blue",
                ))
        finally:
            db.close()
    except Exception:
        pass  # Never block normal commands
```

Note: the callback must NOT break `no_args_is_help=True`. The `if ctx.invoked_subcommand is None: return` guard ensures this.
