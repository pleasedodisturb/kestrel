# GitHub Actions / CI Security Hardening (2026)

Each item: **WHY** / **HOW** / **PITFALL**. Sources cited inline.

## Pin actions by full SHA
- WHY: Tags are mutable; hijacked tags silently run attacker code ([wiz.io](https://www.wiz.io/blog/github-actions-security-guide)).
- HOW: `uses: actions/checkout@11bd71901bbe5b1630ceea73d27597364c9af683 # v4.2.2` ([docs.github.com](https://docs.github.com/en/actions/reference/security/secure-use)).
- PITFALL: Enable Dependabot for `github-actions` or SHAs rot; never use short SHAs.

## `permissions: {}` at root, grant per-job
- WHY: Default `GITHUB_TOKEN` is over-privileged; least privilege blocks lateral movement ([secure-pipelines.com](https://secure-pipelines.com/ci-cd-security/github-actions-security-cheat-sheet/)).
- HOW: Top-level `permissions: {}`; per job add `{ contents: read, id-token: write }`.
- PITFALL: Job-only `permissions:` leaves siblings on org default.

## Concurrency groups
- WHY: Cancels superseded runs; saves minutes, prevents racing deploys ([docs.github.com](https://docs.github.com/en/actions/concepts/workflows-and-actions/concurrency)).
- HOW: `concurrency: { group: ${{ github.workflow }}-${{ github.ref }}, cancel-in-progress: true }`.
- PITFALL: Use `cancel-in-progress: false` for deploys or you abort prod pushes.

## Caching
- WHY: 5-10x faster CI; reduces registry-outage flakiness.
- HOW: `setup-python`/`setup-node` with `cache: 'pip'|'npm'`; or `actions/cache@<sha>` keyed on lockfile hash.
- PITFALL: Cache poisoning — never key only on branch; include lockfile hash.

## Matrix only what you support
- WHY: Each cell costs minutes and review surface.
- HOW: `strategy: { matrix: { python: ["3.11","3.12"], os: [ubuntu-24.04] }, fail-fast: false }`.
- PITFALL: `fail-fast: true` masks per-cell bugs.

## Path filters
- WHY: Skip CI for docs-only changes; cuts queue time.
- HOW: `on: { pull_request: { paths: ['src/**','tests/**'] } }`.
- PITFALL: Required checks + path filters strand PRs as "Expected"; pair with an always-green no-op job.

## Reusable workflows
- WHY: One source of truth for lint/test/deploy across repos ([docs.github.com](https://docs.github.com/actions/using-workflows/workflow-syntax-for-github-actions)).
- HOW: `on: { workflow_call: { inputs:{}, secrets:{} } }`; call with `uses: org/repo/.github/workflows/ci.yml@<sha>`.
- PITFALL: Reusable workflow inherits caller's concurrency — set explicitly.

## OIDC for cloud deploys
- WHY: Short-lived federated tokens replace long-lived cloud secrets ([github.blog](https://github.blog/changelog/2025-08-15-github-actions-policy-now-supports-blocking-and-sha-pinning-actions/)).
- HOW: `permissions: { id-token: write }` + `aws-actions/configure-aws-credentials` with `role-to-assume`; trust policy scoped to `repo:org/repo:ref:refs/heads/main`.
- PITFALL: Wildcard `sub` (`repo:org/*`) lets forks assume the role.

## actionlint + zizmor
- WHY: Catches unpinned actions, template injection, dangerous triggers pre-merge ([zizmor](https://github.com/woodruffw/zizmor), [actionlint](https://github.com/rhysd/actionlint)).
- HOW: Add `zizmorcore/zizmor-action@<sha>` and `reviewdog/action-actionlint@<sha>` as a `lint` job.
- PITFALL: Run on `pull_request`, never `pull_request_target` — the latter runs attacker code with secrets.

## Pinned runner labels
- WHY: `ubuntu-latest` rolls silently; breaks builds on rollover days.
- HOW: `runs-on: ubuntu-24.04` / `macos-14`.
- PITFALL: Old labels are deprecated on schedule; add a quarterly bump task.

## `timeout-minutes:` everywhere
- WHY: Hung jobs burn 6h default; DoS vector.
- HOW: `jobs: { test: { timeout-minutes: 15 } }`.
- PITFALL: No global default — the one missing it is the one that hangs.

## Artifact `retention-days:`
- WHY: 90d default leaks artifacts and inflates storage bills.
- HOW: `upload-artifact@<sha>` with `retention-days: 7`.
- PITFALL: Public repos default to 90d; verify org policy.

## `$GITHUB_STEP_SUMMARY`
- WHY: Surfaces test counts, coverage, links on the run page.
- HOW: `echo "## Coverage: 92%" >> $GITHUB_STEP_SUMMARY`.
- PITFALL: Never echo secrets or untrusted PR titles — Markdown renders.

## Branch protection
- WHY: Blocks direct pushes, unreviewed merges, history rewrites ([docs.github.com](https://docs.github.com/en/actions/reference/security/secure-use)).
- HOW: Require PR reviews, required status checks (strict), signed commits, linear history; block force-push and deletions.
- PITFALL: Admins bypass by default — enable "Do not allow bypassing".

## Required status checks
- WHY: Contract for "main is releasable".
- HOW: Select check names in protection; enable "Require branches up to date".
- PITFALL: Renaming a job orphans the check — PRs block forever.

## Dependabot auto-merge
- WHY: Patch/minor bumps shouldn't need human review.
- HOW: Workflow on `pull_request` with `if: github.actor == 'dependabot[bot]'` + `update-type != 'version-update:semver-major'`; `gh pr merge --auto --squash`.
- PITFALL: Auto-merging majors breaks prod; gate on `dependabot/fetch-metadata`.

## Merge Queue
- WHY: Serializes merges with up-to-date testing; kills "green PR breaks main" races.
- HOW: Enable in branch protection; jobs trigger on `merge_group:`.
- PITFALL: Worth it only above ~5 PRs/day to one hot branch.
