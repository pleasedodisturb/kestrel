# Security Policy

## Supported versions

| Version | Supported          |
|---------|--------------------|
| 1.x     | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a vulnerability

**Do not open a public issue, PR, or Discussion for security problems.**

Use [GitHub's Private Vulnerability Reporting](https://github.com/OWNER/REPO/security/advisories/new) (preferred) or email **<security@example.com>** with PGP key [available here](https://example.com/security.asc).

What to include:
- Affected version(s)
- A description of the impact
- Reproduction steps or proof-of-concept
- Any suggested mitigation

## What happens next

1. **Acknowledgement** within 3 business days.
2. **Triage** within 7 business days — severity, impact, fix plan.
3. **Coordinated disclosure** — we work with you on a public-disclosure date, request a CVE through the GitHub Advisory Database, and credit you in the advisory.
4. We do **not** offer a paid bug bounty.

## Out of scope

- Vulnerabilities in dependencies (please report upstream).
- Issues requiring physical access or non-default configurations.
- DoS via resource exhaustion in self-hosted deployments.
